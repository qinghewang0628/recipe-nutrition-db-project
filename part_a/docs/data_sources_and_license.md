# Data Sources, Provenance and Licence Review

Person A, Data Engineering. This document records why the dataset was
selected, what is known about its origin, and the conservative handling
adopted in the absence of a licence.

---

## 1. Selection

The project requires an ingredient set as a set-valued attribute, plus
multi-predicate filtering, nutrition and cost aggregation, and full-text
search. The course-provided `archive-datasets/` directory contains five
normalised CSV files covering South Asian cuisines and satisfies all four
requirements.

| Requirement | File | Coverage |
|---|---|---|
| Ingredient-set reverse lookup, overlap ranking, rarity weighting | `recipe_ingredients.csv` (103,908 rows) | Yes |
| Cuisine, time, difficulty, cost and rating filters | `recipes_master.csv` (9,997 x 23) | Yes |
| Nutrition range filtering and panels | `recipe_nutrition.csv` (9,997 x 13) | Yes |
| Full-text document (name + cuisine + steps) | `recipes_master.csv`, `recipe_steps.csv` (84,616 rows) | Yes |
| Cuisine dimension and 3NF exercise | `cuisine_metadata.csv` (5 rows) | Yes |
| Dietary flags and allergen exclusion | Four `is_*` flags plus ingredient detail | Raw flags unreliable; see section 4 |

Public recipe corpora such as Recipe1M or Food.com were not used. They are
large, weakly structured, and carry image and licensing constraints that do
not serve the project's focus on set-similarity retrieval and index
scalability. The five normalised tables let the database work concentrate on
inverted indexes, execution plans and scale-tier experiments.

## 2. Provenance review

| Item | Finding |
|---|---|
| Delivery form | Course material directory, distributed with the assignment |
| Accompanying metadata | No `LICENSE`, `README`, `DATASET.md`, source URL, author or version |
| File fingerprints | SHA-256 of all five files in `etl/config.py` and `data/raw/MANIFEST.sha256` |
| Public source search | No exact match for the five-file combination and cuisine set |
| Nature of the data | Programmatically generated teaching data (section 3) |

### Structural evidence

1. `recipe_id` is strictly sequential from `RCP00001` to `RCP09997`, with no
   gaps.
2. The sum of `cuisine_metadata.recipe_count` is exactly 9,997 and each
   cuisine matches the master table (3,000 / 3,498 / 1,500 / 1,000 / 999).
3. Only 20 step templates exist, at most 59 characters each, with no
   semantic link to the ingredients.
4. All 208,523 rows have zero empty cells, zero duplicates and zero orphan
   foreign keys — implausible for crawled data.
5. Numeric columns occupy uniform intervals: rating 3.5–5.0, calories
   150–799, sodium 200–1499 mg, grams 200–999, millilitres 100–499.
6. Dietary labels conflict with ingredients in 32.6%–58.6% of recipes,
   consistent with randomly generated labels.

Accordingly, the dataset is described throughout as a course-provided
synthetic recipe dataset. No claim is made that it represents real recipes,
and no nutritional or dietary conclusion is extrapolated to the real world.

## 3. Licence handling

Because no licence was bundled and no exact public source could be located,
the following conservative policy applies.

| Decision | Implementation |
|---|---|
| Scope of use | DSC5003 coursework only; no commercial or public redistribution |
| Repository contents | The five raw CSVs are excluded by `.gitignore`; only SHA-256 values, `NOTICE.md` and the rebuild script are committed |
| Reproducibility | Members place the five CSVs in `../archive-datasets/` or `data/raw/` and run `make seed`; verification compares against `MANIFEST.sha256` |
| Derived data | `data/clean/` and `data/scales/` are generated by this project's scripts and may be committed; they are labelled derived and synthetic |
| Citation | Cited as an anonymous course-provided synthetic dataset, 2026; no author or licence is invented |
| Open item | The group lead must confirm the original source, attribution and whether public release is permitted |

This is an unresolved risk, not a completed task. The absence of a licence
is not treated as permission to redistribute.

### Comparable public datasets (selection context only)

The following were examined but are not data sources for this project:

- Kaggle, *Top Indian and Pakistani Cuisines Dataset* (MIT): image URLs and
  stringified ingredient lists, not the five-table structure.
- Kaggle, *Recipe Dataset: Ingredients & Cooking Insights* (Apache 2.0):
  500 rows, too small.
- Kaggle, *Recipes Dataset: 64k Dishes* (CC0): requires NLP extraction.
- Hugging Face, *recipes-with-nutrition* (CC BY-NC 4.0): images and
  non-commercial restriction.

## 4. Known technical defects

Licensing aside, the raw data requires ETL treatment: 12,190 dietary label
conflicts, 1,517 free-text quantity strings, 7,996 surplus duplicate
ingredient rows, 143 recipes with extreme quantities, a `Paneer` category
conflict, and step durations that are not a valid time metric. These are
described in `docs/data_profile.md` and resolved in
`docs/cleaning_rules.md`.
